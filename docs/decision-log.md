# 设计决策

## 2026-10-12：Windows 悬浮窗与菜单参考 Mac（v0.1.6 历史方案）

用户要求检查 GitHub Mac 版本，并在悬浮设计和右键弹窗上参考 Mac；同时明确所有“打开主界面”入口都须居中。

参考 [NanfengCodexQuota-Mac 源码](https://github.com/nanzhufeng/NanfengCodexQuota-Mac/tree/4faf1dae1c7b29cfb6ef7bff712cf885ecc0daaa)，检查 WidgetView、ContextMenu、AppDelegate 及共享 Rust 圆窗绘制。远端发布版为 v0.1.6，本轮对照固定在已读取的 main 提交，未在 Windows 上声称运行过 macOS 软件。

- 复用同源 Rust 圆窗色彩与几何：132 逻辑画布、白色主字、深色圆底、红橙黄色环；外沿加宽，内侧位置保持，修复透底与底部黑边。
- Windows 继续使用原生 TrackPopupMenu，保留辅助技术文字、鼠标捕获、键盘选择和退出。菜单逻辑尺寸190×166、13字号、14图标，检查标记在左侧、退出项上方分隔线、低色度悬停；圆角区域仅应用于该线程本次菜单的窗口，钩子与子类状态由生命周期释放。
- 菜单在点击点右上方8逻辑像素展开，按实际工作区避让；材质与阴影使用 Windows 原生能力，不宣称复刻 AppKit 原生玻璃效果。
- 首次与重复打开主界面，统一在当前指针所在屏幕工作区居中。跨 DPI 移动后再次校正最终大小，小工作区收窄窗口；保留用户选择的正常尺寸。
- 悬浮窗双击也进入相同入口。保持静默更新、单请求在途与真实失败提示，不新增常驻按钮，不恢复已明确删除的功能审阅。

验收：圆窗像素合同、菜单锚点/工作区及主窗居中单测；原生菜单尺寸、圆角、Escape、30次开关资源计数；真实 GUI 首次/重复打开和托盘/圆窗双击路径。投递 Home/Down/Enter 窗口消息未能代表真实键盘选择，不据此声明该项通过；真实键盘选择、不同物理 DPI、Windows 主题及长期运行仍需扩大验证。

## 2026-10-12：v0.1.7 菜单软阴影

用户截图确认原生菜单圆角裁剪后仍有矩形边框与硬投影。改为无边框弹窗卡片，保留原生 BUTTON 控件的文字、复选语义和键盘路径；独立 layered window 绘制沿圆角轮廓衰减的透明阴影。阴影窗口不激活、不拦截点击；不修改系统菜单类或全局阴影设置。

190×166 卡片保持原布局，16逻辑像素透明留边、轻微下移投影、最外缘 alpha 为零。成功、取消及捕获丢失均回收卡片与阴影。主界面居中与静默更新保持。

本机验证：96/144/192 DPI 阴影像素渐变与透明边界；无 WS_BORDER / CS_DROPSHADOW、阴影透明/不激活标志、窗口销毁、Escape、Home/Down/Enter 打开主界面、原生命令及30次开关无 GDI/USER 增长。受控白底实际菜单截图人工检查通过；跨物理显示器、读屏软件和长期运行尚未扩大验证。

## 2026-10-12：v0.1.8 悬浮窗置顶与任务栏避让

复现 v0.1.7 两个问题：另一个置顶测试窗口后来出现可盖住悬浮窗；拖动结束仅保存位置，可将悬浮窗放入任务栏范围。原实现仅在显示/配置时设置 TOPMOST，且仅启动/显示器变化时校正位置。

增加独立1秒轻量维护计时器：只有可见、未拖动、未打开自身菜单且用户启用置顶时，遇到上方重叠外部窗口或 TOPMOST 标志被降级，使用 SWP_NOACTIVATE 恢复置顶。无重叠时不反复调整层级；自身菜单/主界面不作为竞争窗口，隐藏与关闭置顶遵守用户选择。

拖动结束、维护以及工作区设置变化时，以当前窗口位置进行工作区校正，避免回跳旧保存位置；拖动进行时暂停校正。Explorer重建任务栏和唤醒也执行维护，退出清理计时器。不注册系统级钩子或修改其他软件。

[Windows GetMonitorInfo 工作区说明](https://learn.microsoft.com/en-us/windows/win32/shell/abm-gettaskbarpos)提供任务栏/其他appbar避让范围；本轮仅使用本机工作区，不修改系统任务栏设置。

QA：scripts/qa-topmost.py 创建并销毁隔离遮挡窗口；旧版两项明确红灯，新版恢复、无焦点抢占、标志降级恢复、拖动不被打断、释放后工作区校正、禁用/隐藏尊重均绿灯。普通桌面窗口与本机底部任务栏验证通过；独占全屏、安全桌面、自动隐藏任务栏和物理多屏差异未实测，不声称跨越系统层级限制。

补充冷启动证据：初版维护方案在安装版冷启动仍失败，运行诊断确认偏好true/visibletrue/draggingfalse但实际TOPMOST标志false，单次HWND_TOPMOST返回成功也未恢复；HWND_NOTOPMOST→HWND_TOPMOST转换可恢复。最终在创建窗口时带上所选TOPMOST扩展样式；标志缺失时先重置层级再提升。修改后的冷启动与降级回归通过；增加偏好/可见/拖动/实际置顶布尔诊断，删除临时阶段计数和1秒诊断写盘。QA等待用户配置与真实样式一致，清理以配置而非瞬时样式为准，避免测试误改用户置顶偏好。

## 2026-10-15：v0.1.9 刷新恢复与安静的断线展示

用户报告刷新频繁失败，随后要求删除秒，以及不再显示“连接失败”。当前本机只读RPC/手动刷新可成功；本轮未把某个代理、DNS或服务端错误猜测为已确认根因。已确认旧策略首次失败等待120秒，连续失败可到600秒，且第一次网络错误即显示失败；用合成只读进程在同一刷新中“先失败后成功”复现旧版不能自行恢复。

- 网络/超时错误仅在同次读取内重试一次，间隔500ms且可取消；认证错误不重试，持续错误仍止于两次读取。耗尽后自动恢复等待为5/15/30/60/120/240/300秒，不并发请求、不发起模型调用；登录/缺少CLI/不兼容等非传输错误按配置正常间隔等待，避免快速轮询。
- 短暂网络/超时错误保留真实最后值和原采样时间，悬浮窗显示上次更新时分；主界面显示中性的“最近更新”，托盘不显示连接失败提示。原错误留在本地failure字段。数据超过原有年龄门限仍显示过期；未获得样本不造数，需重新登录等可操作异常仍提示。
- 悬浮窗、设置和托盘的用户时间统一到分钟。诊断sampled_at仍保留精确采样时间，自动化据此判断同一分钟内成功的新样本，不靠秒数变化制造更新。
- 本轮使用隔离LOCALAPPDATA+合成只读CLI验证成功→持续网络失败→恢复：原59%和时间不变、无失败提示、后台保留失败、恢复后真实新采样生效；不改变用户登录或系统网络设置。

平台边界：真实额度读取恢复已验证；未来外部网络故障本身不受应用保证。没有修改全局UI配方、凭据、代理或其他软件，不新增功能审阅入口。
